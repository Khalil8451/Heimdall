# Security policy

There is no released application or hosted service yet. No production version is currently supported. Future supported release lines and patch expectations will be announced with releases.

Do not report vulnerabilities, private API definitions, source code, tokens, or exploit details in public issues. If the repository's **Security → Report a vulnerability** option is enabled, use [private vulnerability reporting](https://github.com/Khalil8451/Heimdall/security/advisories/new). Its availability has not been verified. If unavailable, ask the maintainer to enable a private reporting channel without including sensitive details; no security email address is invented here.

A report should include affected commit/version, a minimal synthetic reproduction, expected/actual behavior, and impact. Do not test against third-party or production systems. Maintainer acknowledgement/remediation SLAs are not promised while the project is unstaffed; coordinated disclosure arrangements will be agreed with the reporter.

Before a team pilot, the owner must enable and verify private reporting, assign response ownership, and complete the team's internal security review. Internal threat models and implementation plans are maintained outside this repository. Files alone do not enable GitHub security settings; their availability remains unverified.
